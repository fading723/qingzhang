# 隐私检查与数据边界

检查日期：2026-11-01。对象：本仓库的应用代码、配置、依赖锁文件、构建脚本、测试、文档和静态图标。

本次未在待提交文件中发现真实账本、访问令牌、私钥、个人邮箱或本机用户目录；自写业务代码中未发现账本上传接口、广告、分析 SDK 调用或财务数据日志。已处理检查中发现的通知、导出和发布文件问题。**这是一份工程检查记录，不是第三方安全认证，也不代表软件绝对没有隐私风险。**

## 数据如何流动

| 场景 | 数据位置与接收方 |
| --- | --- |
| 原生记账 | SQLite 保存在 App 私有目录，恢复前安全副本也在私有目录中；不配置账本服务器 |
| 网页预览 | 当前浏览器、当前站点的 IndexedDB；与原生 App 数据独立 |
| 周期提醒 | 系统本地通知；默认只显示通用提醒，不展示规则名称、金额、账户或备注；不申请远程推送 token |
| 导入 | 用户主动选择文件后在本机解析，校验通过后整体写入；不发送到云端解析 |
| 导出 | 用户主动操作后生成明文 JSON / CSV，再交给系统分享、文件保存或浏览器下载界面 |
| 备份恢复 | 验证文件后保存当前账本安全副本，再原子替换本地数据 |
| 开发与构建 | npm、Expo/EAS、Android 工具链需要访问各自服务；云构建会接收工程源码。这与账本运行时上传是不同的数据流 |
| GitHub 仓库 | 保存源代码、配置、锁文件、图标、合成测试、说明文档和不含真实账目的 CSV 模板，不保存手机账本或本地构建缓存 |

原生自动更新下载已通过 `updates.enabled=false` 关闭。依赖包出现在构建树中不等于被打进 App 或会上传账本；本次结论基于业务代码、配置和验证范围，不声称逐行审计了全部第三方原生依赖。

## 本次修复

1. **锁屏通知**：移除周期规则名称和无用通知载荷，改用通用文案；Android 通知通道使用 `PRIVATE`。旧版本已排程提醒需要打开新版重新同步，系统通知设置仍由设备控制。
2. **导出临时副本**：每次分享使用独立目录，避免同名覆盖或并发串用。系统分享返回不能证明接收端已读取完，故保留交给系统的副本；后续导出时尝试清理超过 24 小时、且不在活跃分享中的本程序目录。分享前写入失败会立即尝试清理。未知文件和用户保存的原件不删除。
3. **CSV 文本**：补齐换行和全角公式前缀的文本转义，并验证逗号、引号、多行内容及原始单引号的往返。它降低首次打开 CSV 的公式注入风险；电子表格软件另存后可能去掉转义，没有对所有表格软件通用的永久保证。完整备份使用 JSON。
4. **安卓权限**：阻止合并不需要的外部存储读写和悬浮窗权限；文件交换使用用户主动选择和系统分享。框架的网络权限仍可能存在，不把“没有自写网络请求”说成“系统禁止一切网络”。
5. **依赖公告**：构建工具的 `glob` 和 `minimatch` 存在拒绝服务问题，原审计因依赖传播列出 14 项中危记录。通过精确 `overrides` 使用修复版本，保留 Expo 版本，重新检查工具链兼容性；不使用强制降级修复。参见下方安全公告及验证记录。
6. **发布排除**：增强 `.gitignore`，排除环境文件、凭证、签名证书、数据库、账本导出、构建产物、原始日志和本机工具链。源码 ZIP 脚本也不再收录原始测试日志／报告。Git 提交身份使用 GitHub 提供的 noreply 邮箱，不提交个人邮箱。

## 仍需了解的边界

- **没有应用层加密或应用锁。** SQLite、IndexedDB、恢复前副本及导出的 JSON / CSV 均未进行应用层加密；本机保护依赖设备锁屏、操作系统与应用沙盒。当前没有生物识别解锁、后台任务预览遮挡或防截图功能。
- **主动分享可能把文件交给第三方。** 在分享面板选择聊天、网盘或邮件后，接收方会得到所选文件；应用不能撤回外部保存的副本。
- **临时清理是尽力执行。** 24 小时是后续导出触发清理时的判断阈值，不是后台定时删除保证。强杀、崩溃、长期不再导出或系统拒绝删除时，副本可能继续留在私有缓存。旧版本留下的未知目录不自动删除。
- **系统备份已配置排除，仍需设备验证。** Android 禁用备份并排除云备份及设备迁移；iOS 在启动时创建排除备份的账本目录。Expo Go 不代表独立 App 的配置。静态检查不能替代所有厂商、系统版本的实际备份测试。
- **本机存储不等于永久保存。** 卸载、清除数据、设备损坏或网页存储回收都可能丢失账本；应主动导出并妥善保存完整备份。当前网页还不是具备离线冷启动的 PWA。
- **源码更新不改变旧安装包。** 本次修复后需要重新构建、安装，才会进入 App。本地较早生成的 APK 不代表已包含这些改动。

## 检查范围与复现

检查包括待发布文本的密钥／凭证和个人信息模式、初始账本与示例内容、锁文件下载源、图标元数据、应用网络调用和日志、导出／导入路径、通知内容、原生备份配置与 Git 排除规则。依赖漏洞结果依赖 npm 公告库在检查时的状态。

```sh
npm ci
npm audit
npm run typecheck
npm test
npx expo export --platform all
```

浏览器操作测试使用独立上下文和合成账本；不会读取使用者的日常浏览器数据。完整检查结果、历史 APK 的验收范围和待做的 iPhone / Android 实测见 [验证记录](VALIDATION.md)。系统分享接收端读取时机、系统通知及备份排除仍须独立安装包真机验证。
